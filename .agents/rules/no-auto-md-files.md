# Documentation creation

- Do not create a new Markdown file unless the user explicitly requests documentation or an
  existing workflow requires that exact artifact.
- Prefer updating the closest canonical document or rule over creating a recap, status file, or
  duplicate guide.
- Temporary analysis belongs in the task conversation or `/tmp`, not the repository.
- When an approved decision changes a durable product or architecture contract, update the existing
  canonical rule in the same change.
- Do not generate broad README files, migration reports, audit reports, or completion summaries by
  default.
